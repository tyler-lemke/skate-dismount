## Failure and rationale

`main.gd:494–500` derives wall time by dividing render delta by Engine.time_scale,
then changes that global scale in the same callback.
Impact callbacks also change the scale from physics processing.
That makes the provenance of a delta at a scale transition ambiguous.
`main.gd:328–329` discards sample-clock remainder, and recorded frames have no time.
`camera_clock_probe.json` independently measured .055 s sampling at crash rate .55,
while playback assumes .05 s; this is confirmed timing distortion, repaired in R06.
The project currently has 90 Hz physics and no automatic interpolation enabled.
Rider skin updates run in render and pose callbacks; inspect exact ownership before enabling it.
Headless probes cannot prove visible stutter, so the rendered smoothness gate is in R14.

Choose explicit clock domains and presentation ownership because slow motion magnifies
small timing inconsistencies; changing solver rates would alter the physical game.
Keep the 90 Hz physics rate and the existing four time rates initially.
Only change a rate after measured collision and presentation comparisons support it.

## Required clock interface

Define a small clock policy in existing code or a focused helper such as game_clock.gd.
Expose simulation elapsed for RUN and CRASH, presentation elapsed, and effective rate.
Simulation elapsed increments from the actual physics callback delta exactly once.
Presentation elapsed uses Time.get_ticks_usec monotonic samples with an explicit baseline.
Entering pause/help stops gameplay presentation timers and refreshes that baseline.
Resuming must not add the duration spent in a modal.
Handle first sample, route replacement, focus loss, and replay as explicit resets.
Focus suspension refreshes the wall-clock baseline while preserving accumulated run/crash time.
Physics, replay time, and action audio remain suspended until R03 Resume; fuses/idle/deadlines
do not accrue during focus suspension. MENU/RESULTS follow R03 without resetting campaign state.
The same suspension remains when HELP closes into focus-induced PAUSE; only Resume clears it.
Do not call sleep to synthesize normal frame duration.
Do not multiply physics delta by Engine.time_scale a second time.
Impact-left, impact-cooldown, and cascade camera focus use active presentation seconds.
Fuse countdowns, damage/contact cooldowns, and physical settlement use simulation seconds.
The maximum crash deadline remains 34 active presentation seconds.
The ordinary crash cap remains 16 simulated seconds, subject to R09's reason reporting.
The rate priority remains impact .18, held slow .25, crash .55, ordinary 1.0.
Pause prevents motion; time-scale and pause-tree state must agree after every transition.

## Presentation ownership

Simulation transforms are written by physics owners only during live play.
Automatic physics interpolation is enabled only after all transform writers are inventoried.
Camera and live visual-only helpers use a deliberate render presentation path.
Replay transforms are already interpolated manually and must opt out of automatic interpolation.
Avoid a second smoothing layer on the hero that introduces extra visual lag.
For bones driven by external rigid bodies, choose one explicit solution:
read interpolated body transforms in render and drive a non-interpolated visual skeleton,
or compute visual poses on physics ticks and validate skeleton interpolation support locally.
Prefer the first when the installed version cannot interpolate the custom bone writes correctly.
Do not write the same bone pose independently in both callbacks.
Document which transforms are simulation data and which are presentation data.
Reset interpolation after placement, bail transfer, retry, route change, and replay exit.
Never use a visually interpolated body transform as input to injury or contact scoring.

## Risks and rollback

Enabling interpolation alone can make render-written bones jitter more severely.
Clock refactoring can accidentally extend injury payout windows or shorten fuses.
Keep scoring time domains explicit and compare event ledgers rather than totals alone.
If automatic bone interpolation fails, retain physics interpolation for bodies and use
one render-only skin path based on interpolated body transforms.
Rollback only the failing presentation strategy, not explicit timestamps or clock separation.
Do not mask a failure by increasing physics TPS or weakening an error detector.
