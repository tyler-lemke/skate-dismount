## Chosen contract and rationale

Use one action eligibility policy for keyboard events, HUD signals and automation calls.
Put the policy near the phase owner; HUD should request actions rather than bypass it.
Do not solve this by removing Button keyboard focus: menu accessibility must remain.
Track a single visible modal kind NONE/PAUSE/HELP and its explicit return context.
Opening help from a running phase pauses; closing it restores that same phase.
Opening help from MENU or RESULTS does not start a run or reset its result.
If help opens while already paused, closing help returns to the existing pause modal.
Opening pause or help clears charge and slow-motion latches, preserving accumulated charge.
A Space release launches only if its matching press began in eligible READY.
Window focus loss clears all held action latches; return requires a fresh gameplay press.
This prevents a stale release or GUI callback from causing an unexpected launch.
Polling W/A/D and arrow movement must also require active window focus and no modal.
Clear eligibility on phase replacement, retry, route change and replay entry/exit.
Use `get_tree().paused` and the existing `is_paused` flag consistently in every transition.
Preserve the .55/.25/.18 rate policy; R05 later changes clock ownership, not input meaning.

Focus loss in READY/RUN/CRASH/REPLAY enters the existing pause state unless a modal already owns
suspension. Record a focus-suspension latch even when HELP already owns suspension. Focus gain
does not resume. After loss from a live phase during HELP, closing HELP returns to PAUSE,
and only Resume clears the latch. Existing PAUSE return stays PAUSE; MENU/RESULTS keep their
phase and ordinary help return. All held/polled gameplay keys require
release/repress after focus loss, not merely a cleared event latch.

## Action and focus interfaces

Document an explicit phase/action table beside the centralized dispatch implementation.
Mute is a global presentation/preference action in every phase, including PAUSE/HELP.
M uses the authoritative policy, cannot launch/resume/change phase, and respects R02 protected
records/pending state. Help H toggles the active help panel without bypassing focus suspension.
MENU: route/play/help/mute and Button keyboard navigation; no charge, bail or breaker.
READY: pose/hat/steering/charge/camera plus pause/help/retry; no breaker or filing.
RUN: push/steering/bail/held slow/camera plus pause/help/retry; no pose/hat changes.
CRASH: aftertouch/breaker/held slow/file/camera plus pause/help/retry; no charge.
RESULTS: retry/next/route/replay/help/mute and Button navigation; no live gameplay action.
REPLAY: replay camera/retry/pause/help/mute; no live impulses, file or payout action.
Visible PAUSE/HELP controls are the only GUI owners while those modals are open.
Tab and Shift-Tab cycle only the visible modal's enabled controls; Enter activates that owner.
Live Space and Tab receive ownership before GUI navigation in their eligible phases.
Handle press and release together; do not rely on `_unhandled_input` for those actions.
MENU/RESULTS keep ordinary GUI Tab/Enter navigation when no modal is visible.
Restore the previous focus on close only when it is still valid, enabled and visible.
Otherwise choose the phase's first sensible Button or release focus in live gameplay.
Publish action eligibility and modal-transition behavior for R10 UI and R11 audio consumers.
Avoid renaming persistence fields or changing save semantics; R02 owns that boundary.
