## Chosen safety contract and rationale

Validate the actual displayed camera lens, not only a distant desired endpoint.
Use current real world/prop CollisionShape3D geometry on collision mask 3, excluding rider layer 4.
Do not use nominal prop radius, authored mesh appearance or the camera helper as its own oracle.
Check initial overlap separately, since ray/sweep behavior can ignore an intersecting origin.
Use a small lens-volume shape query, initially a sphere radius .18 m, as an explicit safety margin.
Treat .18 as a camera collision envelope, not a promise that every near-plane corner is covered.
Measure near-plane corner clipping in R14 before enlarging this margin or changing projection.
Generate a bounded candidate set near the intended chase/side/overhead composition.
Prefer same-side raises/shifts before mirroring so the rider's screen direction stays readable.
Then test the smoothed/interpolated travel path and final lens against actual solid geometry.
If a path is blocked, shorten it to a safe point or choose a verified alternate, not a blind lerp.
Apply floor, overlap and path corrections before calculating final look_at orientation.
Apply bounded shake to the target, preserving lens safety; shake must not move the lens into solids.
Keep existing chase scale and visible traffic handoff; do not solve obstruction by zooming away.
When no candidate is safe, keep a verified last-safe position or use a documented bounded fallback.
Revalidate last-safe against moving props; stale safety is not a perpetual exemption.
Avoid cycling endlessly among candidates or feeding camera placement back into physics bodies.
