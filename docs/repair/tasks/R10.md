## Required display contract

RESULTS shows three distinct quantities when they differ:
current claim, improvement over the persisted route best, and banked treatment fund.
On commit success, the improvement can say SECURED and the banked fund updates.
On commit failure, show SESSION BEST — SAVE PENDING with the unbanked amount.
Display a concise persistent recovery action labeled Retry Save.
A successful retry updates the persisted fund once without adding the same delta twice.
A replay or weaker attempt never commits another improvement by itself.
The newly funded story ending depends on the persisted total crossing 600000.
Preferences may apply in session when saving fails, with a visible unsaved status.
Unknown future records are protected and ordinary Retry Save cannot overwrite them.
Corrupt-save recovery shows whether a valid backup was recovered and whether it was committed.
If no valid backup exists, continue in a clearly marked session-only mode until an explicit
in-game recovery choice preserves the damaged bytes and creates a fresh current save.
That choice is a player UX decision, not a requirement to ask the developer for permission.

Why: both hiding failed funding and repeatedly banking retries break the campaign trust.
The player needs one clear persistent status and a safe action, not technical stack traces.

## UI layout and focus contract

Keep the established typography, dark panels, orange/mint hierarchy, and existing route art.
Add only the status and actions needed for truthful results and recovery.
Reserve room for claim amount, fund meter, injury summary, and primary retry/replay actions.
Use container-driven layout or explicit anchors that adapt within the supported minimum window.
Choose a documented minimum 960×540 logical viewport if the existing design can support it.
If it cannot, set the real minimum supported size and test that instead of claiming arbitrary sizes.
Evaluate the existing default 1280×800 window and 1440×900 logical canvas.
Also evaluate 1024×768 and 1920×1080 window cases plus high-DPI scale on the target Mac.
No actionable button may be clipped or overlapped by a modal backdrop.
Long dollar strings up to 999999999 and long receipt labels must fit or truncate deliberately.
Do not shrink essential labels to unreadable sizes to satisfy a bounds test.
Color is supplemental: injury stage and save status include text or an icon with a label.
Keyboard focus order follows the visible primary action order.
Opening recovery/help/pause focuses the active panel; closing restores a valid prior control.
Modal input rules belong to R03 and must not be duplicated inconsistently here.
