## Required startup contract

Parse `--records-path=<path>` from Godot user arguments before any record read.
Explicit CLI path wins over a pre-ready injected path, which wins over test-mode defaults.
Normal `user://records.json` is selected only when no explicit override/test fixture exists.
`--test-mode` must never replace an explicit destination, regardless of argument order.
Multiple conflicting explicit overrides or an empty/malformed override fail clearly.
An inaccessible explicit destination remains that destination; never fall back to the user's record.
Accept an absolute isolated filename so packaged native tests can use normal presentation safely.
The override selects storage only; it must not imply automation, headless mode, or muted audio.
Preserve `--test-mode`, `--capture`, and `--self-check` behavior with documented path precedence.
Capture/self-check use isolated storage when no explicit override exists and never a user profile.
If a direct test-mode launch has no override, allocate a fresh project-local per-process fixture.
Construct/create its parent before loading; do not reuse the old shared test filename.
The harness allocates `builds/test_runs/<run-id>/<suite>/` and passes its absolute record path.
Suite fixture creation and selection happen before `root.add_child(game)` triggers `_ready()`.
Remove late hardcoded assignments that redirect saves away from the harness-selected fixture.
Provide one reusable fixture helper rather than independent boot-order logic in each suite.
The reopened persistence scenario uses a fresh process/startup fixture, not only manual load twice.
Keep an explicit negative fixture for missing parents so R02 can test save-open failure.

## Required runner contract

Keep `tools/test.sh` as the documented entry point and honor `GODOT_BIN`.
Add `tools/run_bounded.py` or an equivalently small documented portable process helper.
Its public CLI accepts `--timeout-seconds`, `--log`, then `--` and the argument-vector command.
Use argument vectors, not shell interpolation; preserve spaces in project/engine/fixture paths.
Each run captures combined output, process exit, elapsed time, timeout, and command identity.
Run a child process group; on deadline terminate it, wait briefly, then kill remaining children.
Initial limits: import 180 seconds and each suite 180 seconds; record any bounded override.
Permit explicit 10–600 second developer overrides; neither zero nor an infinite timeout is valid.
The timeout negative fixture uses a short internal deadline so verification does not stall.
Require exactly one expected `NAME: N checks, 0 failures` completion marker per suite.
Names are RULES, INJURIES, INPUTS, GAME, ROUTES, PLAYABILITY, UI, AUDIO, SKATING,
CRASHBREAKER, RIDER_SKIN, TRAFFIC, and CAMERA; existing suffix telemetry is permitted.
Missing, duplicate, wrong-name, malformed, zero-check, or nonzero-failure summaries fail the run.
Do not freeze old assertion totals as an oracle; added meaningful checks can change counts.
Reject SCRIPT ERROR, parse/compile errors, FAIL markers, reported leaks, and unexpected engine errors.
The known macOS certificate diagnostic may be narrowly classified by its exact condition/location.
Do not whitelist all ERROR lines or an arbitrary surrounding block that could hide a later failure.
Engine nonzero exit and timeout fail even when a success-looking summary exists.
Generate a run result JSON from actual outputs, not static hand-maintained counts.
Include engine version, run ID, input-source digest, suite identities/counts, and artifact paths.
Publish summary success only after every expected suite completed with the required checks.
Do not run imports/tests concurrently against shared logs or the same fixture directory.
