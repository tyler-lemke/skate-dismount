## Candidate schema and loading result

Current serialized v2 fields remain `version`, `best_scores`, `legacy_scores`, `muted`, and `hat`.
`best_scores` and `legacy_scores` each contain exactly three route values in route order.
Scores must be numeric, finite, integral, nonnegative, and no greater than 999999999.
Allow legitimate JSON integer-valued numeric representation; reject strings, Booleans, nulls, fractions, and containers.
Support exactly version 1 and version 2; missing version means the established v1 legacy format.
Malformed version values and unsupported versions must not be coerced into a supported number.
For v1, valid `best_scores` become legacy scores and current treatment bests start at zero.
For v2, valid current bests load independently from optional historical legacy values.
Malformed optional mute defaults false, malformed hat defaults 0, and malformed optional legacy defaults zeros.
A malformed optional field must not invalidate an otherwise valid best-score candidate or raise a script error.
For v1, an optional malformed legacy field must never overwrite the migrated valid historical scores.
Validate into temporary typed values; commit all active state only after the whole required candidate passes.
Return `load_state`: `missing`, `loaded`, `recoverable`, `corrupt`, `inaccessible`, or `unsupported`.
Include candidate/default state, diagnostic code, protected original path, and valid backup candidate if present.
Missing means a clean first run; inaccessible/corrupt/unsupported never masquerade as missing.
Retain unsupported newer data byte-for-byte and make that profile read-only for this older client.
No preference toggle or new claim may downgrade it, remove unknown fields, or replace it with defaults.
Keep corrupt required-score input protected; offer a validated backup rather than silently applying zeros.
Expose `recover_backup()` as an explicit operation for R10; do not invent an automatic destructive reset.
If recovery is accepted, preserve the rejected original under a unique local quarantine name first.
Failure to preserve it prevents replacement and yields a checked error; never overwrite a quarantine file.
Reconcile an accepted backup with session improvements by per-route maximum, never additive replay credit.

## Checked saving and recovery contract

`commit(candidate)` returns `ok`, diagnostic code, durable snapshot, and pending candidate.
Serialize a fully validated candidate into a unique sibling temporary file in the same directory.
Check open, store, flush/close status as available in the local runtime, and read/validate the temporary bytes.
Retain the last validated primary as backup before replacing it; do not rotate corrupt input into the good backup.
Inspect every copy/rename/replacement result and keep old recoverable data until the commit is verified.
Verify Godot 4.7/filesystem operation behavior locally; do not assert universal power-loss durability.
Do not use delete-primary-then-rename as an alleged atomic replacement without preserving recovery.
Cold startup handles leftover temporary/backup files with a documented deterministic selection policy.
An uncommitted temp cannot become secured funding merely because it contains a higher score.
Reject writes while the selected profile is unsupported/inaccessible or unresolved corruption remains protected.
Do not silently switch save paths; a failed selected path remains a visible pending-storage condition.
Maintain the session candidate on open/write/replace failure and expose an explicit retry operation.
Preference edits join the pending complete candidate so subsequent success saves both claims and preferences.
After successful commit clear the pending state and use the exact validated committed snapshot.
Repeated retries, finish callbacks, and weaker claims must not add a contribution twice.

## Durable versus session interface for main/HUD

Keep `best_scores` as durable per-route bests and add `session_best_scores` for earned session maxima.
`fund_total()` returns only durable funding; provide `session_fund_total()` separately.
Add `records_status`, `pending_save`, and diagnostic/recovery fields with documented typed values.
Track `session_improvement` separately from `last_money_secured`, which means newly committed durable increase.
Compute a durable contribution from committed maxima versus the prior durable snapshot, never from call count.
On a failed claim save, results retain the earned claim/session best but show no newly secured amount.
Only a successful commit that crosses the goal can produce the newly-funded ending.
Expose a consumable committed-contribution/goal-crossing event so a preference-triggered retry is handled once.
After failure, replay/navigation/retry cannot convert pending money into durable money implicitly.
Sound/ending integrations receive the durable crossing event, not a repeated comparison against session totals.
R10 receives recovery actions, pending-save retry action, durable/session figures, and actionable diagnostics.
Maintain normal loaded preferences and hats even when no new claim is earned.
Do not disable play merely because an old profile is protected; allow clearly labeled session-only progress.
