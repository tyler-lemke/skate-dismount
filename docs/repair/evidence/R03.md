# R03 — Modal focus and gameplay input

The central policy in `scripts/main.gd` owns phase eligibility, modal transitions, focus loss, and held-key generations. `game_hud.gd` validates the visible button owner before dispatch and provides focus traversal within HELP/PAUSE. The repair does not branch gameplay on test mode.

| Phase | Eligible gameplay actions |
| --- | --- |
| MENU | Play, route selection, help, mute |
| READY | Pose/hat, steering, Space charge/release, camera, retry |
| RUN | Steering/push, Space bail, held slow motion, camera, retry |
| CRASH | Aftertouch, one crashbreaker, held slow motion, file, camera, retry |
| RESULTS | Retry, replay, next/route/menu, camera, help, mute |
| REPLAY | Camera, retry, pause, help, mute; no live impulse or filing |

HELP owns its close control, pauses active simulation, and returns to its preceding modal. PAUSE owns Resume, Restart, Route Select, Sound, and Quit. Actual viewport Tab/Shift-Tab traverses the visible controls; Enter/Space cannot activate a covered control. MENU/RESULTS preserve normal GUI key-up activation, including Replay. The application/window focus-loss notifications clear transient charge/slow input, block currently held gameplay keys until observed release, and require an explicit focused Resume. Duplicate notifications preserve the saved control. Natural launch/bail transitions preserve eligible held W/A/D input.

`_replace_route` is the trusted scene construction primitive used by accepted route/retry actions and physical test arrangements. Public `select_route` is phase/modal gated. Test arrangements were changed to the primitive without reducing their original physical assertions. A persistence round-trip arrangement now creates its empty fixture before `_ready`, since R02 correctly retains previously earned durable maxima.
