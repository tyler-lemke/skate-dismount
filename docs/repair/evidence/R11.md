# R11 — Pause and replay audio state

The supported source fix adds `SoundDirector.set_replay_audio` and main entry/exit/reset calls. Replay explicitly stops rolling, traffic, and pooled action voices; `play` and both action-loop updates refuse live effects while replay owns the sound policy. Music continues. The director processes pause changes while the tree is paused and pauses action loops and pooled effects. Traffic gain moves using the active presentation delta rather than simulation delta divided by a newly changed time rate. Master-bus mute and explicit stream detachment on teardown remain intact.

The existing headless allocation guard deliberately creates no AudioStreamPlayer nodes. AUDIO77 validates the fifteen real imported resources and file properties; it does not prove audibility. REPLAY_INTEGRATION's actual entries/exits validate the music-only ownership flag. R12's twenty replay/route replacements check bounded allocations and disposal under this backend.

A separate diagnostic allocated real AudioStreamPlayer nodes under Dummy headless audio and passed18 state assertions, but the process reported leaked playback resources at exit even after an additional mixer-retirement interval. The strict runner correctly rejected both probes. They are retained under `builds/repair_work/integration/audio-policy*.log.result.json` and `builds/repair_work/R11/PROBE_LIMIT.md`. They are not registered as accepted suites and no leak/error whitelist was added. This incomplete diagnostic is not native allocation or listening evidence.

Native service startup and direct graphical LaunchServices connection failed in this environment. Audible mute, replay transitions, pause/resume, mix quality, and device-backed player teardown remain unobserved R14 acceptance. Those limitations block final native promotion, not construction of an explicitly qualified candidate. Any native regression must reopen R11 and rebuild the candidate.
